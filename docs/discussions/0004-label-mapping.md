# 0004 ラベルのマッピング: 意味の近いラベルを、誰がやっても同じになるように統合するには

状態: 議論中
関連: [discussions/0002](0002-separate-implementation-and-use.md)(選別に残ったデータセット)、`local/label_analysis/`(git 管理外。ラベルの分析と、1 段目の統合表)
最終更新: 2026-11-04

## 1. 背景

ラベルの統合を 2 段に分ける(maintainer、2026-11-04)。

| 段 | 何を統合するか | 例 | 性格 |
|---|---|---|---|
| 1 段目(ベース) | 意味が明らかに同じもの: 綴り、語形、略号、翻訳、誤字、番号つきの名前、配布元が対応を書いている番号 | `ANG` → anger、`Colère` → anger、`nuetral` → neutral | 誰がやっても同じになる。済み(`local/label_analysis/label_merge.csv`、151 種類 → 96 種類) |
| 2 段目 | 意味が近いもの | joy と happiness、calm と neutral | 統合のしかたで結果の意味が変わる。この議論の対象 |

2 段目は 1 段目と分けて扱う。1 段目は誰でも使う土台、2 段目は挑戦的な選択。

## 2. 要件

1. **誰がやっても同じ対応表になる。** 判断を人の感覚(「happy と joy は近い」)に頼らない。
2. **科学的な根拠がある。** 根拠は、測定されたデータか、手順の決まった資料。
3. **「先行研究がそう統合している」は、今回は根拠にしない(maintainer)。** 他の研究の対応表をそのまま使わない。区別しておくこと: 他の研究が**測ったデータ**(言葉の意味の評定など)を使うのは、対応表の借用ではなく、測定を根拠にすることである。ここで使ってよいかは決めてほしい(6 節の 2)。
4. **規則と閾値は、結果(認識の精度)を見る前に決める。** 結果を見て規則を変えると、誰がやっても同じにはならない。

## 3. 根拠の候補

### 3.1 データセット自身の設計(共起)

あるデータセットが、2 つのラベルを**別のクラスとして両方持っている**なら、そのデータセットの作者は 2 つを違うものとして定義している。これは DB から機械的に分かる。

フィルタに残った 87 件で数えた例(1 段目の統合のあと):

| 組 | 両方を持つデータセット |
|---|---|
| joy と happiness | 0 |
| amusement と happiness | 0 |
| no_emotion と neutral | 0 |
| calm と neutral | 2(Quechua、RAVDESS) |
| boredom と neutral | 3 |
| sleepy と neutral | 3 |
| frustration と anger | 3 |
| contempt と disgust | 2 |
| excitement と happiness | 5 |
| calm と happiness | 5 |

- **共起は「統合してはいけない」の根拠になる。** 例えば calm と neutral は、RAVDESS が別のクラスとして作っている。
- **共起しないことは「同じ」の根拠にならない。** joy と happiness が共起しないのは、たまたま同じデータセットに無いだけかもしれない。
- 統合を決めるには、別の根拠(3.2〜3.4)がいる。共起は、それに対する**制約**として使える。

### 3.2 言葉の意味の測定データ(感情語の評定)

感情を表す英単語について、多数の人が感情価(valence)・覚醒(arousal)・支配(dominance)を評定した公開データがある(候補: Warriner ほか 2013 の英語の評定、NRC VAD Lexicon。**どちらもまだ読んでいない**。使うなら一次資料を読んでから)。

- 使い方の案: 2 つのラベルの評定値が、**評定のばらつき(測定の誤差)の範囲で区別できない**ときだけ統合する。閾値を「誤差」から決めるので、任意の数字を選ばずに済む。
- 弱点:
  - 3 つの次元に落とすと、区別が失われる。anger と fear は、感情価も覚醒も近いかもしれない(3.1 の共起で守れる: 多くのデータセットが別のクラスにしている)。
  - ラベルの言葉は、データセットの中で定義されたクラスの名前で、辞書の単語とは限らない(例: `surprise (positive)`、`slightly angry`)。評定データに無い言葉は、統合しない。
  - 英語以外のラベルは、1 段目で英語に直したものだけが使える。

### 3.3 語彙資源(WordNet など)

同じ意味の語の集まり(synset)や上位・下位の関係を使う。版を固定すれば誰がやっても同じになる。ただし、関係を決めているのは辞書の編者の判断で、測定ではない。感情の近さを表すようには作られていない。

### 3.4 人の聞き取りのデータ

- 1 つの発話に複数の聞き手がラベルを付けたデータ(IEMOCAP、MSP-Podcast の個々の票など)で、2 つのラベルがどれくらい同じ発話に付くかを数える。声の知覚にもとづくので、最も直接の根拠になる。ただし、両方のラベルを選べるデータセットでしか測れない。
- 新しく聴取実験をすれば、どの組でも測れる。費用がかかる。

### 3.5 音響のデータ(分類器の混同)

学習したモデルが 2 つのラベルを混同するかを見る。**勧めない**: ラベルがほぼ 1 つのデータセットにしか無いので、モデルは感情ではなくデータセットの違いを学ぶ。また、認識の結果で対応表を決めるのは、2 節の 4 に反する。

## 4. 案(Claude の考え)

規則を 3 つ重ねる。どれも事前に決め、スクリプトで対応表を作る。

1. **制約(3.1):** 2 つのラベルが、どれか 1 つのデータセットで別のクラスとして共起するなら、統合しない。
2. **根拠(3.2):** 評定データで、2 つのラベルが測定の誤差の範囲で区別できないときだけ、統合の候補にする。評定データに無いラベルは統合しない(1 段目のまま残す)。
3. **まとめ方:** 統合はグループで考え、グループの中の**すべての組**が 1 と 2 を満たすときだけ同じグループにする(A≈B、B≈C から A≈C を導かない)。

- 結果は「統合した」「統合しなかった(理由: 共起 / 区別できる / 評定データに無い)」をラベルごとに出力する。
- 3.4(聞き取り)は、測れる組だけ、2 の結果を確かめる検証に使う。

この案は、数を減らすことより、**統合したものが確かに同じだと言えること**を優先する。多くのラベルは統合されずに残るはず。

## 5. 2 段目とは別に決めること

- **最後に使うクラスの集合**(例: 7 クラス)をどう決めるか。これは「どれを同じとみなすか」とは別の問い(どのクラスを予測するか)。データから決める案: 多くのデータセットに現れるラベル(1 段目のあとで、7 つが 38〜84 件、8 番目以降は 5 件以下)。
- 「ラベルなし・合意なし」(`no_agreed_label`、`none_(no_majority)` など)と、`other` の扱い。これらは感情の意味ではなく、注釈の結果の状態なので、2 段目の統合ではなく、使う・使わないの判断になる。

## 6. 決めてほしいこと

1. 2 段目の方針: 4 節の案(共起の制約 + 評定データ + グループ全体で判定)でよいか。
2. 他の研究が**測った評定データ**(3.2)を根拠に使ってよいか(2 節の 3 との区別)。
3. 評定データの候補を一次資料で読んで、どれを使うか比べてよいか。
4. 3.4 の聞き取りのデータを、検証に使うか。
