# 0003 ライセンスの区分: 何のために分けるのか

状態: 議論中
関連: [discussions/0002](0002-separate-implementation-and-use.md)(7.5〜7.7 の続き。条件 C4)
最終更新: 2026-11-04(実験の条件を受けて 8 で見直し中)

対象は `local/license/`(git 管理外)の区分と、実験 `multidataset_ser_01` で区分をどう使うか。DB の `license_spdx` は事実(資料の記述)で、この区分は研究の判断なので、区分そのものは `local/` に置く(公開 DB には書かない)。

## 1. 前提(maintainer、2026-11-04)

- **この実験では、ライセンスが明確なら、ライセンスが何であれ使ってよい。**
- **ただし、学習に使うか評価に使うかを、ライセンスで決める。** そのため、明確なライセンスの中でも、**商用利用ができるかどうか(NC かどうか)** が大事な点になる。これまで open かどうかを気にしてきたのは、このため。
- 議論 0002 の 7.5 で「SA 系は除外」とした決定は、この前提を確かめる前のもの。この議論で見直す。

## 2. 問い

1. **SA(継承)は、そのデータで学習したモデルに、どんな影響を与えるか。** それによって、SA のデータを学習側に入れてよいかが決まる。
2. **`research_only` と `restricted` は、NC にまとめてよいか。** 明確に open でないものは、学術研究の目的で使うだけなので、それ以上細かく分ける必要は無いのではないか(学術研究も禁じるものなら別)。
3. **区分は「open / NC / 不明・未確認」の 3 つで足りるか。**

## 3. 資料に書いてあること

Creative Commons(CC)の公式の解説 2 つ。どちらも 2026-11-04 に読んだ。法律の助言ではなく、CC 自身の説明である。

### 3.1 「Using CC-Licensed Works for AI Training」(creativecommons.org、日付の表示なし)

- **ライセンスが効くのは、著作権の許諾が必要なときだけ。** 例外や制限(国の法律による)に当たる使い方には、ライセンスの条件はかからない。著作権がかかるかは国によって違う。
- **学習では、作品を複製することが多い。** また、モデルが学習データの表現を記憶する(memorization)ことがあり、どの程度かを理論的に測る方法は無い、とする。
- **BY(帰属表示):** 学習データとしてなら、データセットの出典へのリンクで足りうる。
- **SA(継承):** BY-SA と BY-NC-SA は、改変物を同じライセンスで出すことを求める。**モデルや出力が SA のデータから作られ、公開されるなら、SA の条件に従うことは、開発者が元と同じ CC ライセンスを付けることを意味する**(「if ... would」の条件つきの書き方)。
- **NC(非営利):** NC のデータで学習するなら、学習中の複製から、学習したモデルの配布まで、すべての段階が商業目的であってはならない。
- **条件がかかる時点:** BY・SA・ND の条件は、作品や改変物を公開したときにだけかかる。NC は、許諾が必要なすべての使い方にかかる。

### 3.2 CC の FAQ(creativecommons.org/faq/、「Artificial intelligence and CC licenses」と「Data」の節)

- ライセンスは、著作権がかかる新しい技術にもそのまま使えるように作られている。著作権の許諾が要らない使い方(フェアユースなど)には、ライセンスは関係しない。
- SA は、作品を改変して公開したときにだけかかる。公開しなければ、SA の条件は生じない。
- テキスト・データマイニングについて: NC のデータは商業目的でマイニングしない。SA のデータの改変物には、同じライセンスを付ける。

### 3.3 GPL-3.0(gnu.org の本文、2026-11-04 に読んだ)

- **§2:** 実行や、他者に渡さない(convey しない)複製・改変には、条件が無い。プログラムの出力は、出力の内容自体が「covered work」に当たるときだけ GPL の対象になる。
- **§0:** 「modify」は、著作権の許諾が要る形での複製・翻案。「covered work」は、プログラム自体か、それに基づく作品。「convey」は、他者がコピーを作れる・受け取れる形での伝播。
- **§5(c):** プログラムに基づく作品を配布するなら、作品全体を GPL で許諾する。
- **データ・データベース・機械学習・モデルへの言及は本文に無い。** そのため、学習したモデルが「プログラムに基づく作品」に当たるかは、本文からは決まらない。分かるのは、公開(配布)しなければ条件がかからない、ということだけ。
- GPL はソフトウェア用のライセンスで、音声データにかけるのは本来の使い方ではない。

### 3.4 ODbL-1.0(opendatacommons.org の本文、2026-11-04 に読んだ)

- **§1.0:** 「Derivative Database」は、データベースに基づくデータベース。内容の相当部分を新しいデータベースに取り出す(Extraction)・再利用することも含む。「Produced Work」は、内容を検索などで使って得た作品(画像・音・文章など)。「Publicly」は、自分や自分の管理下の者以外に向けること。
- **§4.4:** 公に使う Derivative Database は、ODbL か互換のライセンスにする。
- **§4.5(b)(c):** Produced Work を作っても Derivative Database にはならない。組織内部での使用は公ではないので、§4.4 の対象外。
- **§4.3:** Produced Work を公に使うときは、元のデータベースと ODbL を示す通知をつける。
- **§4.4(c):** Derivative Database から作った Produced Work を公に使うと、その Derivative Database を公に使ったことになる。
- **機械学習・モデルへの言及は本文に無い。** 学習したモデルが Derivative Database か Produced Work かは、本文からは決まらない。内部で使い、公開しなければ、継承の条件は生じない。

### 3.5 3.3・3.4 から言えること

GPL も ODbL も、**公開しなければ条件がかからない**点は SA と同じ。公開するモデルが「改変物」に当たるかは、どちらの本文も答えていない。CC が書いている SA と同じく、法的にはっきりしない。

## 4. 整理(Claude の考え)

### 4.1 SA

- 学習に SA のデータを使い、**モデルを公開しないなら**、SA の条件は生じない(3.1、3.2)。
- **モデルを公開するなら**、CC は「同じライセンス(CC BY-SA)を付けることになる」と書いている。モデルが改変物に当たるかどうかは、法的にはっきりしていない(3.1 は条件つきの書き方で、断定していない)。
- したがって、SA のデータを学習側に入れると、**公開するモデルに CC BY-SA を付けるか、その危険を受け入れるか** になる。学習用を「商用でも使える」データにする目的が、「作ったモデルを自由に公開・利用できるようにする」ことなら、SA はその目的に合わない。
- 選択肢:
  - A: SA を学習側(open と同じ)に入れる。モデルを公開するときは CC BY-SA を付ける覚悟をする。
  - B: SA を評価側(NC と同じ)に入れる。学習したモデルに継承の条件が及ばない。評価にだけ使うなら、改変物を公開しないので SA は生じない。
  - C: SA を独立の区分にして、実験ごとに決める。
- **私の考え: B。** 学習側を「モデルに条件が及ばないもの」だけにすれば、モデルの扱いが一番単純になる。評価には SA でも問題なく使える。

### 4.2 `research_only` と `restricted` を NC にまとめる

- 評価に使うだけなら、学習したモデルにデータの条件は及ばない。学術研究で評価に使うことを禁じていない限り、`research_only` と `restricted` を NC と分ける理由は無い。
- まとめる前に確かめること:
  - 学術研究での利用を認めているか(`research_only` は定義上認めている)。
  - `restricted` は、有料や個別の契約。実装済みでは CASIA の 1 件だけで、これは除外リストに入れた(非公式ミラー)。今の実装済みには残らない。
  - 結果(評価の数値)を論文で公開することを禁じる独自の条件が無いか。今の DB の `license_note` を見る限り、そういう記述は見つけていない(すべてを確かめたわけではない)。

### 4.3 区分の案

| 区分 | 意味 | 学習 / 評価 | 含めるもの |
|---|---|---|---|
| `open` | 商用利用ができ、継承の条件が無い | 学習(評価にも使える) | CC0、CC BY、MIT、Apache、ODC-By |
| `noncommercial` | 商用利用ができない、または継承の条件がある(B 案の場合) | 評価だけ | CC BY-NC、CC BY-NC-ND、CC BY-NC-SA、独自の研究用、有料・独自の条件、(B 案なら)CC BY-SA・GPL・ODbL |
| `unclear` | ライセンスが明確でない | 使わない | `none_stated`、`unknown`、引用だけを求めるもの、`conflicting` で決められないもの |
| (未確認) | DB で未確認 | 判定できない | `license_spdx` が空欄 |

- `conflicting` は、0002 の決定どおり、食い違う記述のうち厳しい方の区分をとる。
- `other`(独自の文言で、上に当てはまらないもの)は、1 件ずつ文言を読んで、3 つのどれかに入れる。区分としては残さない。

## 5. 決定(maintainer、2026-11-04)

1. **SA は学習に使う(A)。** SA は `open` に入れる。
2. **`research_only` と `restricted` は NC にまとめる。**
3. **区分は `open` / `nc` / `unclear`(+ 未確認)の 3 つ。** 扱いが同じなので分けない。名前は長い `noncommercial` をやめて `nc` にする。
4. **C4 は「区分が `unclear` でない」。** 区分は C4 で使う・使わないを決めるだけにする。学習・評価の役割は別の列(後で決める)で、区分から決める。
5. **GPL と ODbL は、一次資料を読んでから決める。別扱いにするかもしれない。** 本文は 3.3・3.4 で読んだ。決定は未了。

今の実装は「いったん SA を含めた版」(maintainer、後日変わるかもしれない)。GPL と ODbL は、決まるまで SA と同じく `open` に入れてある(`class_map.csv` の note に provisional と書いた)。

## 6. 実装と結果(2026-11-04)

- `local/license/classes.csv` と `class_map.csv` を `open` / `nc` / `unclear` に書き換えた。独自の文言(`LicenseRef-other`)は仮の区分 `other` で、1 件ずつ読んで決めるまで C4 は「判定できない」にする。
- 実験 `multidataset_ser_01` の C4 は「区分が `unclear` でない」にした。
- 実装済み 102 件の結果: **通過 76、外れ 16、判定できない 10**(SA を除外していた前の版は 60 / 33 / 9)。C4 で外れるのは、区分が `unclear` の 7 件(C4 より前に外れた 2 件を除く)。
- C0〜C3 を通った中で、SA を `open` に入れたときの訓練側の量(RASA は感情 6 スタイルのみ)は、53 件、約 725 時間、約 52 万サンプル(RASA の時間は感情 6 スタイルの実測 279.1 時間)。

## 7. 残っていること

- **GPL と ODbL の扱い。** 3.5 のとおり、公開しなければ条件がかからない点は SA と同じ。公開するモデルの扱いを SA と同じにするか、別にするか。
- **`other` の 5 件の文言**(実装済みは `hindi_ser_vishlb` の 1 件で、今は C4 が判定できない)。
  - `galgame_speech_ser`: GPL-3.0 に、商用利用の禁止と「学習したモデルを公開すること」という条件が足してある。この条件は SA より強いので、`nc` か別扱いかを決める必要がある。
  - `hindi_ser_vishlb`: データベースは ODbL で、内容の権利は元の著者。
  - `atthack`: OpenSLR の表示は CC (BY/NC/ND) で版が書いていない。論文は CC BY-NC-ND と書いている。
  - `basis_global_emotions`、`qlean_japanese_emotional`: Hugging Face のカードが `other` で、本文は読んでいない。
- 学習・評価の役割を決める列(区分から決める)。

## 8. 実験の条件を受けた見直し(2026-11-04)

### 8.1 実験の条件(maintainer、2026-11-04)

1. **学習したモデルは、商用利用のできる open なライセンスで公開する。**
2. **そのため、NC のデータセットは使えない。**(評価だけなら使えるかは、確認待ち。8.4)
3. **データセットは再配布しない。** どのデータセットも、ESPnet のレシピで各自が元の配布元から入手する。

1 の前提は 1 節(「ライセンスが明確なら何でも使える」)と違う。5 節の決定(SA を `open` に入れる)は、この条件の前のもの。

### 8.2 条件から言えること

- **再配布しないので、データセットそのものにかかる条件は生じない。** ODbL §4.2 の通知や §4.4 の継承、CC の SA の継承は、データやその改変物を公開・配布したときの条件だからである(3.1、3.2、3.4)。ライセンスが問題になるのは、**モデルの公開**だけになる。
- **モデルを公開するので、「公開しなければ条件がかからない」(3.5)は使えない。** 公開するモデルが学習データの改変物に当たるなら、継承の条件がかかる。当たるかどうかは、どの本文も答えておらず、法的にはっきりしない(3.1、3.3、3.4)。条件は「商用利用のできる open なモデル」なので、この不確かさをどこまで受け入れるかが判断になる。

### 8.3 区分ごとの扱い(Claude の考え)

| 今の区分・ライセンス | 件数(C0〜C3 を通過) | 時間 | 扱いの案 | 理由 |
|---|---|---|---|---|
| open(CC0、CC BY、MIT、Apache、ODC-By) | 45 | 約 435(RASA は感情 6 スタイルの実測 279.1) | **学習に使う** | 商用利用ができ、継承の条件が無い。BY の帰属表示は、モデルの公開時にデータセットの一覧と出典を添える |
| CC BY-SA 4.0 | 5 | 約 70.6 | **学習に使わない(案 1)/ モデルを CC BY-SA 4.0 で出すなら使う(案 2)** | モデルが改変物なら、モデルに CC BY-SA をつけることになる。CC BY-SA も商用利用はできるが、モデルを使う人にも継承を求める。案 2 にするなら、これ以外の継承つきのデータは入れられない(下の 3 行)。DailyTalk は README が "academic use" と書いており、別に確かめる必要がある |
| Dusha の独自ライセンス(CC BY-SA 4.0 の改変版) | 1 | 約 202.5 | **学習に使わない** | 継承の先が独自のライセンスで、CC BY-SA と両立するかが書かれていない。モデルにかかる条件が決められない |
| GPL-3.0(MELD) | 1 | 約 12.1 | **学習に使わない** | モデルが改変物なら GPL がかかる。加えて、音声はテレビ番組の切り抜きで、論文は fair use と書いている。配布元が音声の著作権を持っているわけではなく、商用のモデルに使う根拠にならない |
| ODbL-1.0(CREMA-D) | 1 | 約 5.3 | **DbCL を読んでから決める** | ODbL はデータベースの権利だけを許諾し、個々の内容の権利は扱わない(§2.4)。CREMA-D は内容を DbCL で出している(DB の記録、本文はまだ読んでいない)。モデルが Produced Work に当たるなら、ODbL は通知だけを求める(§4.3、§4.5(b)) |
| nc(NC、NC-SA、research_only、restricted) | 23 | 約 569 | **学習に使わない** | 条件 2 |
| unclear | — | — | **使わない** | ライセンスが無いか分からない |

- 私の考えは **案 1**。学習を「商用利用ができ、継承の条件が無い」データだけにすれば、モデルに付けるライセンスを自由に選べる。この場合の学習データは **45 件、約 435 時間**。
- 案 2 の場合、モデルは CC BY-SA 4.0 になり、Apache や MIT では出せない。量は約 505 時間(約 435 + 約 70.6)に増える。
- どちらの案でも Dusha は使えない。
- `other` の 5 件(7 節)はこの条件では次のようになる: `galgame_speech_ser` は商用利用の禁止があるので nc。`atthack` は NC-ND なので nc。`hindi_ser_vishlb` は内容の権利が元の著者で許諾されていないので使えない。残り 2 件はカードの本文を読んで決める。

### 8.4 決めてほしいこと

1. **NC のデータを評価だけに使うのもやめるか。** 条件 2 が評価も含むなら、評価セットも open のデータだけになる。今までの呼び名(学習 = Open License set、評価 = Non-Commercial set)も変わる。
2. **CC BY-SA 4.0 の扱い:** 案 1(学習に使わない)か、案 2(モデルを CC BY-SA 4.0 で出す)か。
3. **CREMA-D:** DbCL の本文を読んでから決めてよいか。
4. **5 節の決定 1(SA を `open` に入れる)を取り消し、SA・GPL・ODbL・独自の継承を、`open` と別の区分(例: `sa`)にしてよいか。**

### 8.5 判別不明の扱い(maintainer、2026-11-04)

条件は、**明示的に除外対象のときだけ外す**。DB に書いていなくて判別できないもの(C2 の録音のしかた、C3 のラベルの付け手、C4 の未確認・未決の `other`)は通す。ただし通したものは、結果の表で `pass_unverified` として区別する(外れる条件は明示された `fail` のみ)。

この規則での実装済み 102 件(`local/experiments/multidataset_ser_01/`): 通過 76、判別不明のまま通過 10、外れ 16。ライセンスの区分別では、open が 60 件(うち判別不明つき 7)、nc が 25 件(同 2)、`other` が 1 件。C0〜C3 の判別不明を通すので、open の量は約 725 時間(確認済み)+約 83 時間(判別不明つき)になる。
