# 0002 人の確認 PR を作る道具

状態: 計画(未着手。#77〜#81 が merge されてから始める)
元の議論: [discussions/0001](../discussions/0001-verification-pr-tool.md)(2 章が設計、6 章が決定)
最終更新: 2026-11-04

人が値を確かめた記録(`checked_by=user`)を付けるための PR を、再利用できる公式の道具にする。今の手作業用スクリプトは `local/verification_tools/` にまとめてあり、道具ができたら消す。

## やること

1. 確認リストの表を定義する(`schema/` に足す)。置き場所は `data/verification/`。列は議論 0001 の 2.3 にある。
2. `tools/verify.py` を作る。手順は 3 つ。
   - `draft`: 条件(項目、レシピの有無など)に合う、まだ人が確かめていない行から、確認リストの下書きを作る。
   - `open`: 下書きを 20 行ずつに分け、確認リストだけを足す PR を開く。本文に、確認の仕方とリンクつきの表を書く。
   - `apply`: merge 済みで、まだ反映していない確認リストを evidence に書き込む(`checked_by=user`、注記に PR 番号)。views を作り直し、validate を通してコミットする。
3. validate に規則を足す。
   - `checked_by=user` の行が、merge 済みの確認リストに載っていること。
   - merge 済みで反映していない確認リストがあれば、エラーにする。
   - 確認リストの行が、存在する evidence を指していること。
4. merge 済みの PR #66〜#71(ライセンス 105 行)を確認リストに移す。移したら、注記の PR 番号で確認を認める古い規則をやめる。
5. `docs/manual.md`(英)と `docs/manual.ja.md` の「人による確認」の節に、手順(下書き → PR → merge → 反映)を書く。skill もそこを参照する。
6. 道具を試す。ブラウザ確認の PR(#77〜#81)が merge されたあと、まだ人が確かめていない値で 1 回通して動かす。
7. `local/verification_tools/` を消す。

## 順番と条件

- #77〜#81 が merge されるまで着手しない(今の形のまま merge を待つ。作り直さない)。
- 道具の名前に、作業段階の番号や日付を入れない。
- 資料のキャッシュなど、`local/` にしか無い物に頼らない。必要な物は道具が取りに行く。
