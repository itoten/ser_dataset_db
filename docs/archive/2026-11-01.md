# Discussion record: 2026-11-01

The redesign built on the decisions of 2026-10-31. Each item: question, background, decision, reason.

## 1-a. When is the recipe readme the source?

- **Background.** A-1 said findings of the implementation come from the recipe readme. But some of them are also stated in papers.
- **Decision.** The readme is cited only for what the documentation does not state and only opening the release shows. If a paper or page states the same, that source is cited even when the readme repeats it.
- **Reason.** In that case the readme only restates it and is itself secondary.

## 1-b. Every value has a source

- **Decision.** Names, versions, URLs and free text too. Free text names its source inside the text; URLs are sources themselves.
- **Reason.** Verifiability. The URL errors found (a paper URL pointing at another paper) arose in a column that had no evidence.

## The list of sources

- **Background.** Evidence rows repeated URLs in many spellings and could not say whether a source was the authors' own, a mirror, or which version it described.
- **Decision.** Sources are rows of `sources.csv` (kind, publisher, source type, version described, why it is about this dataset, date checked). Evidence, annotations, aliases and relations point to them. One document is one source per source type; a DOI makes a different document; a readme is one source per recipe and the commit goes in the locator.
- **Reason.** Source facts are written once, and several open questions (free-text evidence, URL evidence, versions, web archives) are answered by the same table.

## C-3, J-1. What the implementation must establish

- **Decision.** Four things: how the data was obtained (with the date), the size of the whole release, files per label, and problems of the release. Documentation values and release values sit side by side. Dropped: audio format, the listening-based signal column, lexical confounding degree, training results, and the recipe tables. Emotion and non-emotion audio are not counted separately; files per label are always given.
- **Reason.** Only facts that need the implementation, that anyone would find, and that help someone choosing a dataset. Results and judgements invite comparing what cannot be compared. Deciding what is "emotion" needs a judgement.

## C-2. How the readme says it

- **Decision.** A fixed `## The data` section about the whole unfiltered release, with a standard disclaimer (a practical reference, not a research result); a method line for every number; observations marked as the author's with what was heard. The DB cites only that section.
- **Reason.** One section lets the DB and readers know which part is about the release and makes rule 1-a mechanical.

## Issues

- **Decision.** Problems of a release are rows of `issues.csv` with a type from a fixed list. A fact that lets a reader judge is written; a judgement ("may be confounded") is not.

## S-1 and the evidence model

- **Question.** How to hold documentation values and implementation values of the same thing.
- **Decision.** Side by side in paired columns (`*_reported`, `*_release`; `access_method`, `access_observed`). Everywhere else one value; if sources disagree the rows are `conflicting` and so is the value. The canonical-row mechanism and the ranking of source types are removed. The stage of checking is derived from the evidence, not typed in. Values with no public source stay as `provisional` rows until replaced.
- **Reason.** Choosing between sources is a judgement. A paired layout shows both without choosing.

## Listening tests

- **Decision.** The DB records that a test exists and where; no accuracy figure. Accuracy depends on classes, modality and how answers were combined.

## Columns

- `recording_context` mixed how the voice was produced, where the audio came from and what it contains. It is replaced by `speech_production` (with `improvised`), `material_origin` and `vocal_content`; settings become sourced notes. `source_rights` becomes the fact of third-party origin plus quoted statements.
- `text_emotion_link` becomes `spoken_text_design`.
- Versions belong to sources (`describes_version`); a version the authors publish under another name or DOI is a separate row.
- `license_note` only where the identifier cannot convey the terms. "The original spreadsheet did it" is never a reason; its traces are removed.
- Label sets are annotation rows with their own annotator, basis and verification; the dataset columns for them are derived from the main set. Annotation items come from a fixed vocabulary; spelling variants are normalised, meaning-changing mappings are left to the user.
- A column of free tags was considered and deferred: it is easy to add and sits badly with "every value has a source". It may be used in `local/`.

## Local information

- **Decision.** Status columns, use decisions, license grouping, recipe settings and benchmark membership leave the public DB. A git-ignored `local/` folder (only its README is tracked) is the user's working space; the license class and its script live there. `via` and `report_path`, which pointed at internal notes, are removed.
- **Reason.** They depend on a project's purpose; recording them publicly breaks neutrality. Users will want to join the DB to their own research, so the repository gives them a place.

## Process

- DB update reports from recipe sessions are discontinued; the DB session reads the recipe and its readme.
- Human verification is by pull request: batches of about 20 values, merged by the maintainer; the maintainer never has to approve their own pull request, merging is the confirmation.
- Continuing questions: when to use a column and when free text (M-6); designing for AI's limited tokens.
